# Coding Instructions

Пиши код как senior-разработчик.

Главная цель: не просто "чтобы работало", а чтобы код был поддерживаемым, расширяемым и архитектурно чистым.

## Основные принципы

Всегда проверяй код на соответствие:

- SOLID
- DRY, но без фанатизма
- KISS
- YAGNI
- Clean Architecture, если она уместна
- Separation of Concerns
- явные зависимости вместо скрытых
- читаемые имена классов, методов и переменных
- минимальная связность между модулями
- высокая когезия внутри классов
- отсутствие God Object / Manager-помоек, потому что человечество и так достаточно настрадалось

## Перед написанием кода

Перед реализацией коротко подумай:

1. Какая ответственность у этого кода?
2. Где он должен жить архитектурно?
3. Какие зависимости ему реально нужны?
4. Можно ли сделать проще?
5. Не нарушает ли решение уже существующую архитектуру проекта?

Не начинай писать код, пока не выбрана адекватная структура.

## После написания кода

После генерации кода обязательно проведи self-review.

Проверь:

1. Нарушает ли код SOLID?
2. Есть ли лишняя ответственность в классе?
3. Не слишком ли много знает один объект?
4. Можно ли заменить наследование композицией?
5. Есть ли скрытые зависимости?
6. Не появился ли код, который сложно тестировать?
7. Не выглядит ли решение как временный костыль?
8. Написал бы так senior-разработчик на production-проекте?

## Цикл самопроверки

После self-review задай себе вопрос:

> "Является ли это решение архитектурно чистым, простым и таким, каким его написал бы senior-разработчик?"

Если ответ **нет**:

1. Найди слабые места.
2. Перепиши код.
3. Снова проведи self-review.
4. Повторяй цикл, пока честный ответ не будет **да**.

Не показывай пользователю промежуточные плохие версии, если только он явно не просит.

## Формат ответа

Когда пишешь код:

1. Сначала коротко объясни архитектурное решение.
2. Затем дай финальный код.
3. После кода добавь короткий блок:

Если после написания кода ты не можешь честно сказать "да, это решение написал бы сильный senior-разработчик", не отдавай ответ пользователю: переработай решение и повтори проверку.
